## Модульность объектов управления

Цель — подключать новый объект управления одним модулем и строкой регистрации, без правок `main.py` и формата сеанса. Описание объекта строится из данных: параметры, сигналы, единицы и форма. Так позже можно будет добавить объекты, которые преподаватель описывает в файле без программирования.

| Этап | Результат | Состояние |
|---|---|---|
| 1. Реестр управляет страницами | Страницы объектов, их снимки в сеансе и проверка снимков подключаются из реестра моделей; тестовый объект со своей страницей работает без правок `main.py` | выполнен |
| 2. Общая страница объекта | Форма строится из описания параметров; учёт устаревших расчётов, фоновые задачи, идентификация, интервалы и настройка PI общие; бак и нагреватель переведены на неё | выполнен |
| 3. Абсорбер в общей схеме | Абсорбер подключается через тот же реестр и ту же страницу, что и бак с нагревателем | отложен: после этапов 1 и 2 новые объекты подключаются без правок `main.py`, а абсорбер остаётся основным рабочим пространством с заданиями, сравнением, отчётами и картой настроек; перенос около 2000 строк не даёт выигрыша ни для новых объектов, ни для этапа 4 |
| 4. Объекты из файла | Преподаватель описывает объект в файле: уравнения, параметры, единицы; формулы разбираются безопасно, без выполнения кода | после этапов 1 и 2, по отдельному согласованию |

Обратная связь студентов и преподавателей пока недоступна. Когда она появится, приоритеты будут пересмотрены по её итогам.
