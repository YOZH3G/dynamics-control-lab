# Лаборатория динамики и управления

[Полное руководство пользователя](docs.md)

Настольное приложение для студентов АТПП, которое показывает причинно-следственную связь:

```text
возмущение → объект управления → изменение выхода → реакция регулятора
```

Программа моделирует абсорбер и нелинейный бак. Абсорбер использует общий материальный баланс газа и жидкости, условную степень извлечения η и динамическую модель первого порядка с запаздыванием. Программа предназначена для учебных демонстраций; для абсорбера равновесие и кинетика массопередачи не рассчитываются.

Текущая версия: **1.12.1**. Два объекта: абсорбер и нелинейный бак. Эксперимент, независимая проверка, ошибки идентификации и PI на неизменных объектах, сохранение работы. [Отчёт о версии](docs/history/STATUS_1.12.1.md), [дорожная карта и дальнейшие этапы](docs/history/ROADMAP_1.12.md).

## Производительность

Внутренние разделители показывают линию нового положения; размеры панелей и графиков применяются после отпускания мыши. Неактивные разделы отключены от компоновки. Ускорены курсор графиков, сохранение неизменённого сеанса и расчёт бака. Малые движения колеса накапливаются; изменённое автосохранение записывается в фоне. [Результаты измерений и ограничения](docs/history/STATUS_1.12.1.md).

## Качество идентификации

Подгонка и независимая проверка показывают ошибку самого отклика, длительность наблюдаемого отклика после запаздывания в единицах T, разрешение перехода и шум исходного участка. Длинная предыстория не скрывает отсутствие отклика, а частые измерения рядом с большим пропуском не делают запись достаточной. Показатели сохраняются и проверяются при восстановлении.

## Ошибки идентификации и PI абсорбера

Оценки K/T/L из CSV настраивают PI, который проверяется на текущей модели абсорбера. Оба канала учитывают знак усиления, ограничения η и концентраций. Доступны пять требований, сетка ошибок, три отклика, сохранение и CSV/HTML/PDF. Источник оценки и физический объект сохраняются отдельно.

## Ошибки идентификации и PI бака

Списки ошибок K/T и отклонений L используются для настройки PI на одном неизменном нелинейном баке. Пользователь задаёт пять требований, выбирает сочетание ошибок и сравнивает перенастроенный PI с исходным и номинальным. Вся сетка сохраняется в сеансе; доступны CSV/HTML/PDF. [Дорожная карта 1.9](docs/history/ROADMAP_1.9.md).

## Общие результаты моделей

Выбор объектов и запуск расчётов используют реестр встроенных моделей. На странице «Результат модели» доступны общие графики, снимок JSON и экспорт CSV/HTML/PDF. Сигналы с разными единицами разделены на группы; концентрации хранятся в долях и показываются в процентах. Учебные формы, идентификация и специализированные отчёты сохранены. Старые сеансы версий 2/3 открываются.

[Дорожная карта 1.8](docs/history/ROADMAP_1.8.md) описывает общий контракт и проверку подключения моделей. Пользовательские плагины и редактор уравнений в этот выпуск не входят.

Для каждого из семи сценариев доступны варианты с номерами от 1 до 30; вариант 1 сохраняет исходную конфигурацию, остальные детерминированно изменяют параметры расчёта. Пользовательские сценарии и настройки интерфейса сохраняются в `%APPDATA%\AbsorptionTrainer`. Запись выполняется атомарно, а предыдущая корректная версия сценариев хранится в резервной копии. Если основной файл повреждён, программа загружает резервную копию и предлагает восстановление. Сценарии используют JSON версии 2. Сеансы записываются в версии 3; версии 2 и 3 читаются. Сеансы 1.6 открываются как работы с абсорбером; формат версии 1 отклоняется. Каждый опыт хранит параметры модели.

## Модель

Стационарные цели обеих фаз рассчитываются по общему переносу компонента:

```text
J = η · Gг · Xг
Gог = Gг − J
Gна = Gа + J
Xог = (Gг · Xг − J) / Gог
Xна = (Gа · Xа + J) / Gна
```

Базовые входы: `Gг = 1000`, `Gа = 7400` кг/ч, `Xг = 0.5`, `Xа = 97/370`, `η = 0.8`. Они дают `J = 400`, `Gог = 600`, `Gна = 7800` кг/ч, газовую концентрацию `1/6` (примерно 16,67%) и жидкостную `0.30` (30%). В интерфейсе входные концентрации и η задаются процентами.

При возмущении изменяются соответствующие входные параметры, затем пересчитывается общий баланс. При постоянной η изменение только расхода газа не меняет газовую стационарную концентрацию. Это свойство выбранной учебной модели.

Динамика каждого выхода задаётся звеном первого порядка:

```text
T · dy/dt + y = yуст(t − L)
```

По умолчанию `T = 10` с, `L = 2` с, горизонт опыта — 100 с. Стационарные цели удовлетворяют балансу; сглаженные переходные выходы не описывают накопление массы. Регулятор изменяет η в допустимом диапазоне с исходным смещением 80%; для газового и жидкостного выходов направление действия различается.

## Требования

- Python 3.14;
- Tkinter/ttk;
- NumPy;
- Matplotlib с поддержкой Tk.

В официальной сборке Python для Windows Tkinter обычно уже включён.

## Установка и запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

Если необходимые библиотеки уже установлены в выбранном интерпретаторе, достаточно выполнить:

```powershell
python main.py
```

## Проверка

Полный набор модульных тестов запускается командой:

```powershell
python -m unittest discover -s tests -v
```

Для измерений на своём компьютере:

```powershell
python main.py --performance-check performance.json
# Для готового приложения:
.\DynamicsControlLab.exe --performance-check performance.json
```

Проверка использует временный сеанс, показывает тестовое окно и записывает время операций, память, нагрузку процессора в покое и максимальный интервал обработки событий при автосохранении. Код 0 означает завершённое измерение, а не прохождение порога скорости. Рядом появляется файл `.ready`, отмечающий завершение создания интерфейса; время распаковки EXE и импорта в `gui_construction_s` не входит.

## Сборка Windows-приложения

Установите зависимости сборки и запустите сценарий:

```powershell
python -m pip install -r requirements-dev.txt
.\build_windows.ps1
```

Проверенный результат создаётся по пути `dist\DynamicsControlLab.exe`. В сборку включается встроенный комплект сценариев.

Версии прямых и транзитивных зависимостей закреплены в `requirements.txt` и `requirements-dev.txt`. Для воспроизводимой проверки используйте отдельное окружение Python 3.14.7 без системных пакетов. Сценарий сборки проверяет готовый EXE: запуск интерфейса, семь сценариев, идентификацию учебного CSV, полный цикл бака с PI и экспортом CSV/HTML/PDF и восстановление обоих объектов. Дополнительно проверяются ошибки идентификации и PI на баке и абсорбере, экспорт и восстановление этих опытов, общий просмотр, JSON и экспорт результатов обеих моделей. Результат находится в `build\release-check.json`. Измерения EXE сохраняются в `build\performance-check.json`.

GitHub Actions проверяет `trunk` и запросы изменений на Windows и Linux. Linux использует виртуальный экран для тестов Tkinter. После успешных тестов Windows собирает и проверяет EXE, затем сохраняет приложение и руководство во вложении к запуску проверки.

## Сравнение опытов

После расчёта откройте «Результаты» и нажмите «Добавить текущий расчёт». Измените параметры, повторите расчёт и закрепите следующий опыт. На странице «Сравнение» можно:

- показать все или только выбранные переходные процессы;
- сравнить `T`, `L`, регулятор, максимальное отклонение, время установления и статическую ошибку;
- удалить отдельные опыты или очистить текущую выборку;
- экспортировать выбранные опыты в CSV и графики сравнения в PNG;
- переименовать опыт, вернуть его параметры в форму;
- сохранить историю в JSON и открыть её в следующем запуске программы.
