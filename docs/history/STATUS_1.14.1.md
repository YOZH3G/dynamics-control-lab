# Версия 1.14.1: модульность объектов управления

Видимых изменений интерфейса и расчётов нет. Версия меняет устройство программы, чтобы новый объект управления подключался одним модулем и строкой регистрации.

## Объекты подключаются через реестр

Описание модели в реестре теперь указывает страницу объекта в интерфейсе и проверку снимка объекта в сеансе. Главное окно создаёт, рисует и восстанавливает страницы объектов, выводит ошибки их фоновых расчётов и показывает общий результат по реестру, без отдельного кода для бака и нагревателя. Формат сеанса не изменился: сеансы 1.14.0 и более ранних версий открываются как прежде.

## Общая основа страницы объекта

Страницы бака и нагревателя построены на общей основе. Форма собирается из описания параметров модели, подписи полей не изменились. Общими стали учёт устаревших расчётов, фоновые задачи, интервалы K, T и L и цикл «свободный отклик → K, T, L → настройка PI». Обе страницы совпадают с прежними попиксельно. Тестовый объект получает страницу только из описания модели — так позже смогут подключаться объекты, описанные в файле.

Перенос абсорбера в ту же схему отложен: новые объекты подключаются и без этого, а абсорбер остаётся основным рабочим пространством с заданиями, сравнением, отчётами и картой настроек. Причины записаны в [дорожной карте](../../ROADMAP.md).

## Сборка

Страницы объектов загружаются по имени из реестра, и PyInstaller сначала не включил их в сборку: проверка готового приложения в CI на Windows не прошла. Теперь все модули интерфейса включаются в сборку явно. Локальная сборка воспроизвела ошибку на прежнем коммите, а с исправлением прошла полную проверку выпуска.

## Проверка

Полный набор: 228 тестов. GitHub Actions на Linux и Windows проверяет исходники, собирает приложение, запускает проверку выпуска и замеры. Руководство вычитано целиком, PDF пересобран.

Текущие приоритеты — в [дорожной карте](../../ROADMAP.md).
